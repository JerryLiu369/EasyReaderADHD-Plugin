# 03 · Jev 机制与适配：为什么它是「法官」不是「分词器」

## 3.1 Jev 一句话

发 **state（一段上下文）+ 一组类型化问题 questions**，返回**带概率的结构化答案**，
不生成文本、不用解析、输出形状被 schema 锁死。三种原语：

- `choice`：从固定选项选一个（分类/路由）。
- `score`：按有序量表打分（返回概率加权分数 + 各等级概率 + confidence）。
- `noul`：yes/no 判断，返回 `noul` = yes 的概率（0–1），无 confidence 字段。

一次请求可并行问多个问题（同一 state），延迟约 70–500ms/批，输出 token 免费或极便宜。
来源：`jevmodel.net/zh/docs`（注意页脚声明：该站是独立运营产品，与 TypeSafe 无隶属关系；
官方接口是 `api.typesafe.ai`，接入前以英文原版文档为准）。

## 3.2 为什么比 LLM 适合「哪些词高亮」

| 维度 | LLM 生成 span | Jev 打分 |
|---|---|---|
| 输出 | 自由文本，需解析 offset，易漂移 | 每个候选一个 0–1 概率，形状固定 |
| 延迟 | 逐 token 生成，秒级 | 单次前向，百毫秒级/批 |
| 成本 | 输出 token 最贵，而本任务输出最长 | 输出免费/极便宜，只付输入 |
| 密度控制 | 让模型「挑 30%」≈ 许愿 | 按概率排序取 Top-K，滑块 = K，数学上稳定 |
| 校准 | 无 | 返回校准概率 + confidence，可设阈值 |

一句话：**LLM 是让作者写字，Jev 是让评委打分**。高亮是打分问题。

## 3.3 诚实短板（中文项目必须正视）

1. **不做分词**：Jev 不返回 span。Q1（哪里断）仍需一个候选器，只是要求从「切准」
   降为「高召回」（宁多切、勿漏切），法官负责过滤。
2. **中文弱一档**：官方中文站（playground 页）明示「以英文训练为主，中文也能判断，
   但准确度略低于英文」。中文必须实测，不可默认迁移英文结论。
3. **联网 + 花钱 + 文本离机**：打破老项目「完全离线」承诺。你已接受联网付费，
   但隐私文案（PRIVACY.md）和架构必须重写：文本要出机、要缓存、要给开关。
4. **问题设计决定上限**：问「这个词是不是名词」= 把老错误重演一遍；
   必须问可删性（§3.4）。一题只问一件事是官方强调的纪律。
5. **state 粒度 = 段落，不放大到整篇**（MVP v4 实证）：整篇 state 下问题失去段落焦点
   （「损害本段理解」变「损害整篇理解」，谁都高），token 还 ×3–10。
   截图段的怪是候选卫生问题（引号粘连/数字单字/锚点复用），分数本身分得开，已修。

## 3.4 请求原型（中文段落级 noul 批量打分）

```json
{
  "model": "jev-latest",
  "state": "他在北京立方庭参观自然语义科技公司，重点了解了新发布的中文分词工具。",
  "questions": {
    "w_0": {
      "type": "noul",
      "instructions": "如果读者没注意到这个词，理解本段会受损吗？",
      "criteria": {
        "true": "删掉后段落主干、人物、地点、关键动作或结论变模糊",
        "false": "虚词、语气词、删掉不影响理解的修饰"
      }
    }
  }
}
```

实际调用时 `w_0 … w_n` 每个候选一个问题（instructions 里带上候选词本身），
一并发送，返回 `{w_0: {noul: 0.93}, …}` 后按分排序取 Top-K。
备选：`score` 三档（0 可删 / 1 辅助 / 2 主干）+ 按加权分排序，调试时可解释性更好，
但首版建议只用 `noul`，问题纪律最简单。

## 3.5 worked example（本段的期望行为）

- 候选器输出：`[北京立方庭, 参观, 自然语义科技公司, 了解, 中文分词工具, 发布, …]`
  （切得粗一点没关系，碎片如「的/了」也在候选里，等着被打低分。）
- 期望排序：`自然语义科技公司 > 中文分词工具 > 北京立方庭 > 参观 > 了解 > 发布 > … > 的/了`
- 密度 30% → 取前 30% 候选渲染，其余原文不动。

如果实测排序长期把虚词打高、专名打低 → 问题 wording 或中文能力不达标 → 回到 §3.3 第 4 条改 wording，
两次改不好则判 Jev 不可用，换本地微调路线（见 04）。
