# 01 · 概念：从第一性原理看阅读辅助

## 1.1 英文为什么简单（Jiffy Reader 已够用）

英文有空格，词边界免费。Bionic Reading / Jiffy Reader 的逻辑是纯排印的：
**把每个词的前半加粗**，给眼睛提供每行的落点。不需要懂语义，不需要词典，不需要模型。
所以英文这题跟 NLP 无关，你做中文才是对的选点。

## 1.2 中文为什么难：两个耦合问题

中文无空格，一个中文阅读器必须同时回答：

- **Q1 哪里断（segmentation）**：「自然语义科技公司」断成 自然/语义/科技/公司 还是 自然语义/科技公司？
  断错则高亮的 visual chunk 就是错的，看起来「完全不对」。
- **Q2 哪些值得留（salience）**：一段里 30 个候选词，高亮哪 8 个能帮人抓住主干？
  这不是词性问题。「的」「了」是虚词好排除，但名词之间也有主次：
  「他在**北京立方庭**参观**自然语义科技公司**」——地名和公司名哪个更值得高亮取决于上下文，
  静态词典给不出答案。

老项目把 Q1 和 Q2 都交给了同一个静态词典，一错俱错。

## 1.3 关键概念定义（后面文档统一用）

| 概念 | 定义 | 反例 |
|---|---|---|
| 候选（candidate） | 页面文本上的一段 span，有起止 offset，不一定是语言学上的词 | 前向最大匹配切出的单字 |
| 重要性（salience） | 删掉该候选后，读者理解本段受损的程度；是上下文相关的函数，不是词的静态属性 | 「公司」在词典里永远是名词，但重要性随段落变 |
| 密度（density） | 每段高亮候选占全部候选的比例，用户滑块 0–100% 控制的是它 | 老代码的 `Math.random() < density`：密度对了，选的词是随机的 |
| 锚点（anchor） | 高亮词在视觉上的作用：每行 1–3 个落点，均匀分布，不断行碎裂 | 满屏高亮 = 没有锚点；随机高亮 = 锚点落在虚词上 |

## 1.4 「效果好」的操作定义（可测，不过感觉）

1. **可删性**：遮住高亮词，读者复述主干变难；遮住未高亮词，复述基本不变。
2. **密度稳定**：滑块 30% 时，每段实际高亮比例都在 25–35%，不随段落长度漂移。
3. **锚点均匀**：每行至少 1 个锚点，不出现连续三行无高亮。
4. **断词不脏**：高亮 span 不切开固定搭配（成语、专名），宁可粗一点不断错。
