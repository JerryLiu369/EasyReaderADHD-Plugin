# ADHD 中文阅读器（Jev 版）· 文档原型总览

> 目标：中文为主。英文已有 Jiffy Reader（按空格粗体前半词即可），中文无空格，
> 必须同时解决「哪里断词」和「哪些词值得高亮」。本文档原型先把概念和逻辑钉死，再写代码。

## 先说结论

- Jev **不能解决分词**，它是个判断模型（state + 类型化问题 → 带概率的结构化答案，不生成文本）。
- Jev **能解决你老项目真正的病**：用「哪些词删掉会损害理解」代替「词性词典 + 随机密度」。
- 新架构 = **候选器（高召回、便宜）→ Jev 法官（批量打分、排序）→ 渲染器（按密度取 Top-K）**。
- 中文是 Jev 的弱项（官方：英文训练为主，中文可用但精度低一档），所以必须先做小规模中文实测，再决定建不建。

## 文档地图

1. `01-概念.md` —— 第一性原理：阅读辅助到底在做什么，定义断词/重要性/密度。
2. `02-老方案病根.md` —— 你老代码为什么效果不对（定位到文件和函数）。
3. `03-jev机制与适配.md` —— Jev 是什么、为什么比 LLM 适合这题、中文短板、请求原型。
4. `04-新架构与路线图.md` —— propose→judge→render 管线、成本延迟账、评测集、一步步实现顺序。
5. `05-呈现设计.md` —— 加粗而非色块、标什么、密度甜点 5–15%、标错比不标更坏。
6. `06-算法管线.md` —— **v14 冻结版的实现复述**（候选器/法官/渲染器，与 `eval/mvp.py` 逐条对应）。
