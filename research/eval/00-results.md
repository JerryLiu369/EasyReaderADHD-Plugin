# Eval 实测记录（Go/No-Go 依据在此累积）

## E0 · 连通性 + 中文首测（2026-10-12）

- Key 有效，endpoint：`https://api.typesafe.ai/v1/systemone`（官方），模型 `jev-1.13.0`。
- 脚本：`eval/smoke_test.py`（中文 wording）、`eval/wording_en_test.py`（英文 wording）。
- State（同一中文段落）：他在北京立方庭参观自然语义科技公司，重点了解了新发布的中文分词工具。

| wording | 关键词「自然语义科技公司」 | 虚词「了」 | 分离度 |
|---|---|---|---|
| 中文 | 0.45 | 0.23 | 0.22（弱，易混入噪音） |
| 英文 | 0.76 | 0.27 | 0.49（可用，排序明确） |

初步结论：**state 用中文原文，instructions 用英文**。符合官方「英文训练为主」，
也符合 skill 建议（问题定义越贴近模型训练分布越好）。中文 wording 不是不能用，
但同样阈值下误杀/漏标会多一档，留作备选。

## E0 附：token 账（按实测 usage）

- 2 题/请求 ≈ 422–448 input tokens → **约 215 tokens/题**（state 短，指令占大头）。
- 投影：一段 30 候选 ≈ 6.5k input tokens；一页 20 段 ≈ 130k tokens。
- 延迟：国内直连 980–1380ms/批（含 TLS）。并发 3 时整页约 10–20s，需可视区优先 + 缓存。
- 花多少钱取决于单价（等用户给预算上限）， token 量级先记在这里。

## E1 · 正式评测（2026-10-12，20 段真实语料）

- 语料：3 篇少数派长文（产品评论/科技史/影视文化），`eval/corpus/corpus.json`；
  澎湃因反爬不稳定放弃（`__NEXT_DATA__` 结构时有时无，已记录）。
- 方法：每段 1 请求，keys（5–7，我标）+ distractors（4，虚词+硬负例）混合批量打分。
- 脚本：`eval/e1_run.py`，结果：`eval/e1_results.json`。

| 指标 | 结果 | 门槛 | 判定 |
|---|---|---|---|
| P@K（K=keys 数） | **0.881**（随机基线 ~0.6） | 显著高于随机/老词典 | ✅ |
| P@3 | **1.00**（20/20 前三全是关键词） | — | ✅ |
| 虚词误伤率 | **0.0** | <10% | ✅ |

05 文档的 floor 规则修订为**纯排序 Top-K%**，floor 暂缓。

## MVP · 整链跑通（2026-10-12，同日）

- 管线：`eval/mvp.py`（Node Intl.Segmenter 候选 → Jev 批量 noul → Top-12% + 每句锚点 + 相邻平滑 → HTML）。
- 输入：跑步拉伸全文 17 段；输出：`eval/mvp_out.html`。延迟 ~0.5s/批。
- 批量效率：25 题/批 ≈ 2400 input tokens（~96 tokens/题，state 复用摊薄）。

## MVP v7 · 群友意见 + 我打标对齐（2026-10-12，同日）

### 群友意见裁决
- 收：单行宽度 38em→34em；加粗加左右 padding（0.08em）；锚点单位细化到子句（，；：、也切分），
  但只给 ≥15 字长子句补锚（短子句强制会密度膨胀）。对应直觉：目光跟踪负担来自长连续字符——与 01.4 锚点均匀一致。
- 不收：只加粗名词/动词。与 E1 证据冲突（词性≠重要性；Bell/Ponce），且会漏掉非名词关键项。
  他的真实意图（长子句要有落点）已由子句锚点实现。
- 另修出两个真 bug：三字候选膨胀（约定不以实际类纯词三连）→ 只允许含单字的三连；
  首字虚规则误杀（地代缴首字地）→ 改首单元规则（首单元是单字虚词才丢）+ 的/是开头一律丢。

### 我打标对齐（`mylabels.json` 8 段，我精读标的 ground truth）
- 基线（v1 wording）vs 我的标：话题词虚高、归属/标签词（华尔兹 101 位/0.29、吉尔平 70 位、均势理论 35 位）
  与具体例证（制衡手段 84 位、异地代缴 61 位）系统性偏低。
- wording-v2（转述-specificity：谁/哪个理论/什么机制例证，缺了转述变模糊）：8 段中 6 段 mean rank 提升，
  华尔兹 101→4、吉尔平 70→3、异地代缴 61→10、黄精五黑粉 11→3。
- E1-20 独立验证：P@K 0.881→**0.922**，key 均分 0.616→0.693，dis 不变。**采用 v2**，
  WORDING_VER→en-v2，全量重打分。单字串/三字规则同期落地。
- 残留（已知不等式）：四单元链（黄精五黑粉）组不成候选，核心片段（五黑粉 0.85）兜底；
  超密段落 coverage 截断会漏掉排名 15 左右的词（如异地代缴 0.83），属精度/召回权衡，不修。

## 架构复核 + 消融（2026-10-12，同日，`tune6.py`/`ablate.py`）

- 动因：用户要求从头思考 + 朋友建议的“B 架构”（Jev 出关键动词名词等角色信号，代码做选择）。
  形式化为 composite scoring 实验：Jev 每词一个 choice（专名实体/术语概念/关键动作/数据例证/
  一般话题词/虚词填充 6 角色），代码用无权重映射 1-p(话题)-p(虚词）排序。
- 结果：ROLE P@K **0.910** < v3 0.929，且 token ×2。错误全是角色误判（三亚→entity 但不重要、
  这里→entity、第二天→evidence）——角色对但重要性错，修它等于回到起点再加 5 个权重（过拟合）。
  **否决 B 架构**，保留 Jev 直出重要性 + 代码做政策层。朋友直觉的合法部分已在 STOP/FUNC 卫生层。
- 消融（E2E coverage，E1-20 全链路）：
  full 0.465 / no-stop 0.482 / no-func 0.456 / **no-trigram 0.500** / no-runs 0.465 /
  no-substr 0.465 / no-mergecap 0.465 / minimal 0.500。
- 解读：① 三字层是净负资产——E1-00/01 的粘连碎片（行工具Mole/位来自全球/收了60K）几乎全是三字拼的，
  **删除三字候选**（异地代缴由双字地代缴+首单元规则覆盖）；② STOP 表 E1 中性偏负（+0.017），
  例表拟合嫌疑成立，待 multi 渲染验证 junk 率后定夺；③ runs/substr/mergecap E1 零效应，
  但各自由 multi 渲染实证支撑（单字 27→0、重复清零、10 字怪串），保留；④ FUNC 保留（-0.009 +
  省 ~30% 问题数，真金白银）。
- 教训：v3 wording 缓解了粘连排序，但粘连的生产源头（三字）在候选层，prompt 修的是下游。
  层间归因要靠消融，不要靠感觉。
